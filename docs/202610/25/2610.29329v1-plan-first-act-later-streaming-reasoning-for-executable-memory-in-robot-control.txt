## ABSTRACT 

Long-horizon robot manipulation requires a robot to remember task-relevant in-formation beyond its short observation window. Existing memory-augmented policies typically retrieve relevant information from history and reason over it at execution time, placing a heavy reasoning burden on the high-level model. To address this challenge, we propose PAL (Plan first, Act Later), a hierar-chical memory framework for vision-language robot manipulation. It main-tains a short-term visual buffer, a semantic-event memory, and an executable 

subtask list . A high-level vision-language model (VLM) converts stream-ing visual observations into the subtask list . At execution time, the VLM selects the currently relevant subtask from the subtask list and passes it to a low-level vision-language-action (VLA) policy. To teach the model what to write to memory and when to update it, we introduce a two-stage data gen-eration procedure that first expands sparse update supervision and then uses self-labeling with task-grounded verification to generate training data that better match the state distribution encountered during execution. We evaluate our ap-proach on memory-dependent benchmarks and real-world manipulation tasks. On RoboMME, PAL achieves a 56.05% success rate, outperforming the strongest baseline, FrameSamp-Modul, at 44.51%. In real-world experiments across four manipulation tasks, PAL reaches 60.83% overall success, surpassing MemER (45.00%) and FrameSamp-Modul (28.33%). These results show that proactively writing future-relevant subtasks into hierarchical memory improves long-horizon visual reasoning and robot control. Code and videos can be found on our website: 

https://qinghangliu.github.io/pal-webpage/ 

## 1 INTRODUCTION 

Vision-language-action (VLA) models have made substantial progress toward general-purpose robot control (Intelligence et al., 2025b; Kim et al., 2024). By grounding language instructions in visual observations and actions, VLA provides a flexible interface for solving diverse manipulation tasks in generalizable open-world. However, many existing policies still rely on a Markovian or near-Markovian view of the world: the action to execute is assumed to be recoverable from the current observation or a short window of recent frames. This assumption becomes fragile in memory-dependent settings, where successful behavior may depend on historical information observed much earlier. For example, repetitive manipulation requires remembering progress (Yang et al., 2026; Dai et al., 2026; Chen et al., 2026a) and active exploration requires retrieving the location or state of an object discovered earlier when the robot revisits the scene (Shah et al., 2026; Sridhar et al., 2025). To address these memory-dependent challenges, recent works augment VLA models with a memory bank that retains task-relevant information from past observations. At execution time, the model retrieves relevant entries from the bank to support stable long-term decision making (Torne et al., 2026; Sridhar et al., 2025; Shi et al., 2026). Such banks often contain redundant information, making it difficult for the model to fetch the required information and lead to more task failures. One key observation is that: Evidence for defining a future goal are available before executing the goal. As illustrated in Fig. 1, the task requires the robot to press the button and then pick up the highlighted cube. While the robot is still pressing the button, the model can store the future subtask “pick up the cube” in the subtask list when the cube is highlighted. When the transient highlight disappears, the robot can simply retrieve the stored subtask for execution, without re-identifying which cube to pick up. This pattern occurs in many memory-dependent robotic tasks, where the future plan can be determined once the necessary evidence becomes available. Motivated by this view, we propose Plan First, Act Later (PAL ), a hierarchical memory pipeline for VLA long-term decision-making. It comprises a three-level memory system: a short-term vi-sual buffer, a semantic-event memory, and an executable subtask list . These three memory components have distinct roles: the visual buffer retains recent observations, the semantic-event memory maintains task-relevant events, and the executable subtask list stores future-relevant subtasks text instructions. At each query, a high-level vision-language model (VLM) updates the event memory and the subtask list , then selects the subtask to execute for the low-level VLA. This design has two benefits: (1) first, streaming memory updates incrementally compress the visual history, reducing the context required for long-horizon reasoning; (2) second, the stored subtasks can be directly retrieved without searching across a large memory bank for subtask inference. To teach the model what to write to memory and when to update it, we propose a two-stage training pipeline. The pipeline combines dense update-timing supervision with self-labeling and a task-grounded verifier, allowing the training data to better reflect the model’s execution rollout distribution. Evaluation results on RoboMME (Dai et al., 2026), a benchmark of long-horizon, memory-dependent manipulation tasks, show that PAL achieves a 56.05% success rate, compared with 44.51% for the strongest baseline, FrameSamp-Modul. In real-world manipulation experi-ments across four tasks, PAL reaches 60.83% overall success, outperforming MemER (45.00%) and FrameSamp-Modul (28.33%), demonstrating the practical benefits of our approach. Our contri-butions are as follows: • We introduce PAL , a hierarchical memory architecture with a streaming-style reasoning mech-anism for VLA long-term decision-making. It progressively transforms streaming visual obser-vations into semantic events and executable subtasks, providing a structured memory for diverse long-horizon, memory-dependent tasks. 2Preprint. • We develop a two-stage training pipeline that enables the model to learn reliable hierarchical-memory update behavior. It produces accurate and timely memory updates, yielding reliable executable subtask lists for long-horizon reasoning. • We demonstrate the effectiveness of PAL through evaluations on long-horizon, memory-dependent manipulation tasks, where it delivers consistent gains over competitive VLA and memory-augmented methods in both simulated and real-world settings. 

## 2 RELATED WORKS 

Vision-language-action models for robot control. Recent VLA models have evolved from instruction-conditioned visuomotor policies into general robot control systems. Early efforts such as OpenVLA and π0.5 established a unified interface that maps language instructions and visual ob-servations to low-level actions (Kim et al., 2024; Intelligence et al., 2025b). More recent systems improve generalization through larger-scale training, broader robot data, and continued experience-driven learning (Intelligence et al., 2025a; 2026; Team et al., 2026). Despite this progress, most VLA policies still operate on the current observation or a short recent context, motivating hierarchi-cal planning and memory mechanisms for tasks that require information from earlier history. 

Hierarchical planning and subgoal-conditioned control. Long-horizon robot tasks are often handled with a hierarchical interface, where a high-level model selects a subtask or subgoal for a low-level policy to execute (Intelligence et al., 2025b; Shi et al., 2025; Chen et al., 2026a). This interface separates selecting the next subtask from generating the low-level actions that execute it. 

τ0-VLA extends this hierarchy with execution memory and world-model-guided test-time compu-tation, predicting and comparing candidate subtask outcomes before commitment (Cai et al., 2026). Our work adopts the similar interface: the low-level policy executes the current subtask, and the high-level model maintains the semantic state needed to select future subtasks. However, the hier-archical interface alone does not specify how to use information from earlier observations, which motivates memory-augmented VLA methods. 

Memory-augmented VLA models and benchmarks. Memory-augmented VLA methods ad-dress this missing component by storing and retrieving historical information for high-level decision making. Recent works use amortized multi-frame context (Jang et al., 2025), multi-scale embodied memory (Torne et al., 2026), experience retrieval (Sridhar et al., 2025), keyframe-based memory (Chen et al., 2026b), structured scene memory (Ju et al., 2026), and perceptual-cognitive token memories (Shi et al., 2026). HiMe introduces hierarchical embodied memory for long-horizon VLA control, providing another memory-bank approach (Ji et al., 2026). In parallel, benchmarks such as RoboMME, RMBench, and RoboMemArena highlight that robotic policies often fail when task success requires retaining and using historical information (Dai et al., 2026; Chen et al., 2026a; Lei et al., 2026). Although these methods make past information accessible, they still require the high-level model to search a large memory bank at execution time, so the computational cost grows with the amount of stored history. In contrast, our method allows the model to record a future-relevant subtask as soon as the supporting evidence is observed, before the subtask must be executed, and later select it from the editable subtask list . Concurrent work, MaP-WAM (Zhao et al., 2026), similarly plans ahead and stores future-relevant information in memory. However, MaP-WAM plans only the next step, whereas our editable subtask list retains all inferred future subtasks and serves as a persistent component of the memory system. 

## 3 PRELIMINARIES 

Problem setup. We consider memory-dependent VLA tasks in which the correct behavior at timestep t may depend on information that is not visible in the current observation. Let L denote the language instruction, ot the visual observation, at the low-level action, and Ht = {(oi, a i)}ti=1 the raw interaction history. Long-horizon tasks are increasingly challenging for a fully history-based policy π(at | Ht, L ) since the visual context grows with time and contains many redundant frames. 

Hierarchical memory formulation. We organize task memory at three temporal scales. The short-term visual buffer Vt stores recent RGB images from the current observation window. The 3Preprint. other two components are ordered lists of natural-language entries. The semantic-event memory Et

We propose a two-stage training procedure to teach the model what to write to the subtask list and when to update it, while jointly training it to predict the current subtask at each query. Stage 1 augments the training data by creating additional training examples from each sparse annotation. However, this augmentation changes the training data distribution, introducing a mismatch with the model’s inference distribution. We therefore introduce Stage 2 to regularize the model’s memory-update behavior and reduce this mismatch.

This section answers the following questions: • By how much does PAL improve success rates on memory-dependent manipulation tasks compared with baselines? • Why does PAL perform better than baselines on long-horizon tasks? • How do the two training stages contribute to PAL ’s overall performance? • How does PAL perform in real-world robotic manipulation tasks compared with baselines? 5.1 SIMULATED EXPERIMENTS 

RoboMME benchmark and baselines. We evaluate our model on the RoboMME benchmark (Dai et al., 2026), which is a collection of long-horizon, memory-dependent tasks for robotic ma-nipulation. We compare PAL with five baselines. π0.5 uses only the current observation and task instruction, providing a memory-free reference without access to observation history. FrameSamp-Modul (Dai et al., 2026) uniformly samples frames from the observation history and injects their visual features into the policy through feature modulation, providing a perceptual-memory base-line without explicit high-level reasoning. MemER (Sridhar et al., 2025) retrieves relevant experi-ence from the observation history and uses a VLM to produce a grounded subtask for the low-level VLA. PAL adopts the same high-level–low-level control interface, and the low-level VLA used by MemER is identical to that of PAL . EventVLA (Yang et al., 2026) is an end-to-end VLA that learns 6Preprint. to retain sparse, task-relevant keyframes in its Keyframe Evidence Memory. It provides a com-plementary comparison between PAL ’s semantic, executable memory and learned visual evidence memory. Finally, GPT-6-astra + VLA replaces PAL ’s fine-tuned high-level VLM with GPT-6-astra while using the same low-level VLA, and represents its memory as a language description of the cur-rent environment from which it predicts the next subtask. 5.2 ABLATION STUDY 

To validate the effectiveness of our two-stage training approach, we conduct ablation experiments on the RoboMME benchmark. We compare four variants: (1) Sparse Label , trained on data that annotate event or subtask-list updates only at the end of each evidence chunk; (2) Stage 1 Only ,which uses only the densified supervision from the reference teacher without self-labeling; (3) Up-date Gate , which uses the Stage 1 checkpoint together with an additional ground-truth update gate provided by the environment at inference time. Similar to the gate in Sec. 4.3, it opens an update slot when each interval reaches 80% of its duration; the slot remains open until the VLM produces its first non-empty update, and any update outside the active slot is discarded. (4) PAL is our complete approach with both stages and streaming updates. All of them use the same hierarchical memory architecture and low-level VLA policy as PAL . The only difference is the training procedure and the update gate used at inference time. 

Q3: How do the two training stages contribute to PAL’s overall performance? Table 1 re-ports group-level averages, with the full per-task results in Appendix C.1. Stage 1 Only achieves 

37 .35% overall success, Sparse Label improves to 43 .39% , and PAL reaches 56 .05% . To explain these differences, we examine the update behavior in Table 2 on four representative streaming-reasoning tasks. PatternLock and RouteStick involve a large number of list updates as evidence arrives, whereas VideoPlaceOrder and VideoPlaceButton require evidence to be accumulated over a long video stream. Comparing Stage 1 Only with Update Gate, we find that applying the update gate greatly improves final-list accuracy. This is because Update Gate provides the model with approx-imate update timings, thereby decoupling when to update from what to update. The improvements on the final-list accuracy implies that Stage 1 helps the model learn what content to update, but not when to update it. We then calculate the update frequency of each variant. As expected, Stage 1 Only tends to update the executable list too often, since the model is trained with a dataset that over densifies the update timing. Sparse Label under-updates and even fails to update any subtask list for Long-video tasks, which implies sparse supervision is insufficient for learning the correct update behavior. PAL ’s update frequency is closer to ground truth and yields higher final-list accuracy. This suggests that Stage 2 regularizes the overly frequent update behavior learned in Stage 1, producing more accurate memory states for long-horizon reasoning. 5.3 REAL -WORLD EXPERIMENTS

These results suggest that converting streaming observations into hierarchical, executable memory preserves the task-relevant events needed for real-world long-horizon manipulation, rather than relying on lossy frame sampling or retrieval from raw history. 

## 6 CONCLUSION 

We presented PAL , a hierarchical memory pipeline that incrementally converts streaming visual observations into semantic events and a subtask list before they are needed for control. By separating early subtask construction from execution-time selection, PAL reduces the need to repeatedly revisit a large visual history. We further introduced a two-stage training procedure that combines dense update supervision with verified self-labeling to learn reliable memory updates under the model’s rollout distribution. Experiments on RoboMME and four real-world manipulation tasks demonstrate that PAL improves memory-dependent robot control, particularly when relevant evidence must be retained over long horizons. While PAL improves upon prior work, it still has limitations. Its executable memory is represented as a sequential subtask list and therefore cannot encode conditional branches during execution. Pro-grammatic planning methods such as Code as Policies demonstrate that executable programs can express conditional control flow and perception-dependent behavior (Liang et al., 2023). We use the following three cases: 1. Episode-start tasks. The ordered subtask list can be determined at the beginning of the episode. Before enough evidence is available, the list is left unchanged. subtask list . The rules for this timing and mapping are defined separately for each task. 3. StopCube. This task does not require a separate event annotation. At each timestep, we set the executable subtask list to the current subtask itself, so the list and the subtask are identical. Thus, depending on the task, a sparse sample can supervise an event update, a subtask list up-date, or both. Between two update points, the memory state is kept unchanged. Stage 1 subsequently expands these sparse update points into a timing band with multiple query timesteps, as described in Sec. 4; this expansion is separate from the sparse-label construction above. C.3 IMPLEMENTATION DETAILS AND BASELINES 

We first describe the PAL implementation and evaluation protocol, followed by the configurations of the comparison methods. 

PAL. The PAL training setup is described in Appendix B. Table 6 summarizes the inference and evaluation protocol. We evaluate PAL with 50 episodes per task for each seed. For tasks with a conditioning video, we feed the video to the robot as a stream, even though the entire video is available at the beginning. This setting is practically meaningful because it evaluates the model’s ability to reason in real time. 

Baselines. For the π0.5, MemER, and FrameSamp-Modul baselines, we use the results reported by RoboMME (Dai et al., 2026); the original paper evaluates each method using three policy check-points and three seeds per checkpoint, yielding nine evaluation runs in total. 

EventVLA. We adapt the original EventVLA implementation by using the frames annotated as event or subtask list updates in PAL as keyframes. We also implement a streaming keyframe-selection procedure that selects keyframes from the history video as it is observed. All other settings follow the default EventVLA configuration. For long-horizon tasks, we increase the maximum number of stored keyframes to eight to accommodate tasks that require more historical evidence. The model is trained for 100k steps, with a maximum of eight keyframes at inference time. 

GPT-6-astra + VLA. We adopt a structure similar to that of (Torne et al., 2026), in which memory is maintained as a language description of the current environment. At each query, the VLM reads the four most recent frames and decides the next subtask for the low-level VLA to execute. For 16 Preprint. the conditioning video, we sample one frame every 33 frames, using at most 24 frames; for videos shorter than 100 frames, we provide at least three frames. This baseline uses the same low-level VLA as PAL but is evaluated with one seed because repeated API calls incur substantial evaluation time. C.4 MORE ANALYSIS 

C.4.1 GPT-6-ASTRA + VLA We analyze the results of GPT-6-astra + VLA to identify its failure modes. 

Failure mode 1: insensitivity to subtle environmental changes. The model cannot reliably detect small changes in the scene. For example, whether a button has been pressed is visually subtle, so the model often cannot judge whether the press succeeded and therefore does not output the next subtask. This is reflected in its failures on ButtonUnmask and ButtonUnmaskSwap, where it performs notably worse than on the similar tasks VideoUnmask and VideoUnmaskSwap, which do not require pressing a button. 

Failure mode 2: loss of rapidly changing historical information. GPT-6-astra achieves the second-best performance on the Long-video tasks, yet fails on Short-video tasks such as Route-Stick and PatternLock. These tasks are information-dense and their evidence spans only a short interval, so uniform downsampling does not retain enough information. 

Failure mode 3: unstable high-level–low-level interface. The model does not interface reliably with the low-level policy. On tasks such as BinFill and VideoUnmask, the high-level VLM must specify which cube or box to pick. However, the bounding box it outputs jumps frequently from one location to another, which interrupts the motion of the low-level VLA. C.4.2 PAL PAL also performs poorly on InsertPeg, StopCube, and RouteStick. InsertPeg requires precise manipulation to align and insert the peg. In the 250 evaluation episodes, 101 ended in timeout because the peg was not inserted within the allowed horizon, contributing to the low success rate of 4.8% . StopCube requires the robot to anticipate the motion of a dynamically moving object and react quickly enough to press the button at the right moment. These fine-control and rapid-reaction requirements are outside the main scope of this work, which focuses on memory update and long-horizon reasoning. RouteStick exposes a different limitation: the high-level subtask selection and the low-level action execution are not always well coordinated. In an auxiliary experiment, reducing the action-chunk size from 16 to 8 increased the RouteStick success rate from 22 .4% to 46 .0% ,suggesting that finer execution granularity substantially improves this coordination. 

## D REAL -WORLD EXPERIMENTAL DETAILS 

D.1 DATA COLLECTION AND PROCESSING 

We first use gripper actions and intervals in which the robot arm remains stationary to obtain coarse temporal annotations of each trajectory, providing initial estimates of action and subtask boundaries without frame-level manual annotation. We then provide these coarse annotations together with the recorded trajectory videos to GPT-5.6-Sol for fine-grained annotation; GPT-5.6-Sol refines the temporal boundaries and produces the task-level labels used to construct the event and executable subtask supervision. Finally, we remove the stationary portions identified during this process while preserving frames around gripper transitions, subtask boundaries, and task completion, synchronize the remaining front and wrist RGB observations with the robot states and actions, crop and resize both views using fixed camera-specific regions, and re-index the trajectory. Each retained action is rewritten to target the next retained observation, yielding the final action-aligned trajectories used in our experiments. 17 Preprint. Inference runs on a single NVIDIA RTX 4090 GPU, and the inference computer commu-nicates with the robot through an SSH-based ROS bridge. Ex-cluding network latency, the VLA generates action commands at approximately 10–12 Hz. D.3 EVALUATION PROTOCOL 

We apply the same task-specific evaluation criteria to all methods to ensure fair comparisons. Video-PlaceOrder, PatternLock, and VideoUnmask use pre-recorded conditioning videos to reduce the manual effort required during evaluation. For PickXtimes, Levels 1–3 contain 5, 3, and 2 episodes, respectively. For VideoPlaceOrder and PatternLock, Levels 1–4 contain 3, 3, 2, and 2 episodes, re-spectively. VideoUnmask has no difficulty levels and uses 10 episodes under its fixed setting. Each episode is repeated three times, yielding 30 evaluations per task. Across all tasks, an episode is marked as a failure if it exceeds the limit of 1,300 timesteps or triggers the robot arm’s safety lock. 

PickXtimes. An episode is successful if the robot lifts the green box off the table exactly the specified number of times and subsequently keeps its arm raised for 100 timesteps without reaching down to pick up the box again. Any additional contact with the box after the required number of repetitions is counted as a failure. To reduce evaluation time, a trial is also terminated and counted as a failure if any individual pick-and-place cycle takes more than 650 timesteps. The robot arm and the green box start from the same fixed positions in every episode. 

VideoPlaceOrder. An episode is successful if the green box is on the designated target area when the gripper releases it. A placement is considered valid if the box’s vertical projection overlaps the target area. An episode fails if the box is outside all target areas upon release or touches an incorrect target area. The green box is initialized at the center of the workspace, and the robot arm starts from the same fixed pose in every episode. 

PatternLock. An episode is successful if the gripper visits the grid points in the prescribed order. A grid point is considered visited when any part of the gripper passes directly above it. An episode fails if the gripper leaves the grid region or passes over an incorrect grid point. At the beginning of each episode, the gripper is closed and the robot arm is placed at the initial point of the target trajectory. 18 Preprint.
