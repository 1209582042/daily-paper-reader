ABSTRACT
Spatial understanding is essential for embodied agents navigating and interact-
ing with the physical world. As observations arrive incrementally, agents must
reason in a streaming manner. Yet streaming understanding must also be closed-
loop: task-relevant evidence may require both recalling past observations and ac-
tively acquiring new views. Existing streaming approaches largely emphasize
processing incoming observations, leaving task-driven active exploration under-
explored. We introduce MemAct, a framework for streaming spatial understand-
ing with memory and action.
A shared vision–language model incrementally
writes structured historical memory, retrieves records and past frames on demand,
and acquires additional evidence through movement and turning. Retrieved ev-
idence and action observations inform subsequent decisions, enabling the agent
to continue exploring or answer within a unified reasoning loop. We develop the
MemAct suite, a data generation pipeline and collection across real and simulated
environments, with approximately 1M training examples for spatial reasoning,
memory writing, retrieval, and exploration. Its MemAct-bench comprises 20,000
main QA pairs evaluating current-observation understanding, historical evidence
use, and active exploration, plus 2,000 separate Timing questions. MemAct com-
bines supervised fine-tuning for memory and interaction with counterfactual ac-
tion optimization using cumulative evidence gains, action costs, and terminal an-
swer quality to improve exploration and stopping decisions. Experiments show
that MemAct outperforms existing spatial understanding and streaming baselines
and approaches frontier multimodal models on MemAct-bench while retaining
streaming inference efficiency.

INTRODUCTION
Spatial understanding enables embodied agents to reason about objects, their locations, geometry,
and relationships while navigating and interacting with an environment (Yang et al., 2024a;b; Huang
et al., 2022; Jatavallabhula et al., 2023; Gu et al., 2023). In a live setting, observations arrive incre-
mentally (Das et al., 2017; Gordon et al., 2017; Yokoyama et al., 2023): future views are unavail-
able, previously seen objects may leave the visual context, and some task-relevant details may never
appear unless the agent changes viewpoint. A spatial question may therefore be answerable from
the current view, require recalling an earlier observation, or require acquiring a new one. Stream-
ing spatial understanding is consequently a closed-loop process in which the agent uses available
evidence to decide whether to answer, retrieve history, or explore.
Recent streaming work advances spatial reasoning over incrementally arriving observations (Xu
et al., 2025; Yu et al., 2026; Wang et al., 2025b). Yet these methods generally follow a predetermined
camera stream: earlier evidence may leave the retained context, while needed views may never
be acquired (Yang et al., 2024b; Hong et al., 2026). Active embodied QA systems choose new
viewpoints, often using geometric maps or structured spatial memories (Jiang et al., 2025; Yang
et al., 2024b; Ginting et al., 2025). Some also retain experience from before a question arrives. We

study a complementary challenge: training a single streaming VLM to build retrievable memory
as RGB observations arrive and, once queried, decide whether to retrieve earlier evidence, acquire
a new view, or answer. Each result informs the next decision, without supplying depth maps or a
reconstructed 3D map to the model at inference time. Figure 1 contrasts this memory-and-action
loop with offline and passive streaming QA.
This setting poses three distinct challenges. First, a streaming VLM must preserve potentially useful
evidence before knowing the question, even as earlier views leave its limited context. Second, once
queried, it must determine whether the needed evidence is visible now, recoverable from history, or
obtainable only through a new camera view. Learning this distinction requires causal supervision
over what the agent has seen and what its actions reveal. Third, an informative view may require
preparatory movements with little immediate gain, so training must credit their delayed value while
teaching the model when to stop exploring and answer.
We introduce MemAct, a simple design that makes memory and exploration native decisions of a
streaming VLM. The model processes incoming RGB observations incrementally and periodically
generates compact, timestamped records linked to stored frames. When queried, it uses the same
generation interface to answer, request past evidence, or select a discrete camera action. A a simple
rule-based interface returns the requested records or frames, or the resulting new view, to the model
for its next decision. This lets the VLM learn what to record, retrieve, and observe without a separate
spatial planner, depth maps, or a reconstructed 3D scene map as model inputs. (Section 4)
For data construction, we introduce MemAct-data, a data suite that combines streaming spatial QA
with supervision for memory writing, retrieval, and multi-step exploration. An automated pipeline
constructs approximately one million training examples from real and simulated visual streams;
constructed action supervision from changes in target visibility, enabling the model to recognize
insufficient evidence and learn how to explore for more informative views. We also introduce
MemAct-bench, with 20,000 questions testing reasoning from current, historical, and newly ac-
quired observations, plus 2,000 separate questions testing when to answer. (Section 3)
For training, supervised fine-tuning establishes the shared memory, retrieval, exploration, and an-
swering protocol. To credit preparatory actions with delayed benefits, bandit-based counterfactual
optimization compares camera actions and immediate answering from the same causal state through
multi-step continuations. Cumulative evidence gains, action costs, and terminal answer quality en-
courage useful exploration beyond immediate gains while learning when to stop; supervised QA and
memory replay preserve existing capabilities (Section 4.4).
On MemAct-bench, MemAct-9B achieves 67.27% overall multiple-choice accuracy and 60.23 nu-
merical mean relative accuracy, compared with 61.39% and 48.65 for StreamingVLM. Its aggregate
scores are close to those of the evaluated GPT-6 Astra model, while it leads the separate response-
timing evaluation. Ablations show that explicit memory substantially improves questions requiring
historical evidence, and that active exploration and counterfactual optimization improve questions
requiring new views. MemAct also remains competitive on established spatial reasoning bench-

RELATED WORK
Spatial Understanding.
Recent work advances spatial understanding through dedicated bench-
marks (Azuma et al., 2021; Ma et al., 2022; Fu et al., 2024) and spatially grounded training
data (Chen et al., 2024; Cheng et al., 2024; Song et al., 2024). VSI-Bench (Yang et al., 2024a)
evaluates spatial relations, measurement estimation, and spatiotemporal reasoning from indoor
videos. SAT (Ray et al., 2024) synthesizes static and dynamic spatial QA in simulation, while
Cambrian-S (Yang et al., 2025a) develops VSI-590K and spatial training, extending to contin-
ual sensing through latent frame prediction and surprise-driven memory management. These ap-
proaches strengthen spatial reasoning over supplied visual evidence. MemAct contributes an au-
tomated pipeline that constructs supervision for historical memory, retrieval, and multi-step explo-
ration in streaming spatial QA.
Streaming Spatial Understanding.
Streaming methods address causal processing and efficient
retention of continuously arriving observations (Zhang et al., 2024; Yao et al., 2025; He et al.,
2024). StreamingVLM (Xu et al., 2025) combines a compact KV cache with overlapping-chunk
SFT to align training and streaming inference. Stream3D-VLM (Yu et al., 2026) integrates incre-
mental geometry priors and geometry-adaptive voxel compression for online spatial understanding.
StreamEQA (Wang et al., 2025b) evaluates perception, interaction, and planning across backward,
real-time, and forward reasoning on recorded videos. StreamingBench (Lin et al., 2024) evalu-
ates online understanding; VideoChat-Online (Huang et al., 2024) and LiveCC (Chen et al., 2025)
develop memory-based processing and real-time commentary, respectively. MemAct additionally
learns observation acquisition: the model retrieves historical evidence or executes camera actions,
incorporates their outcomes, and decides whether to continue exploring or answer.
Active Perception.
Active perception acquires task-relevant evidence through viewpoint selection
and environmental interaction (Majumdar et al., 2024). EXPRESS-Bench (Jiang et al., 2025) eval-
uates the exploration and reasoning capability of VLMs. ESI-Bench (Hong et al., 2026) evaluates
the perception–action loop through perception, locomotion, and manipulation, exposing failures in
action selection and premature commitment despite insufficient evidence. MemoryEQA (Zhai et al.,
2025) uses structured memory throughout exploration, while Mind Palace (Ginting et al., 2025)
combines long-term recall with exploration and stopping. MemAct contributes a shared streaming
VLM trained for memory writing, retrieval, and camera-action selection, with cumulative-return
optimization of exploration and stopping using downstream evidence and answer quality.

3.1
OBSERVATION CONSTRUCTION AND EVIDENCE ALIGNMENT
Simulated observations use 3D-FRONT (Fu et al., 2021) layouts and assets after removing conspicu-
ously interpenetrating or implausibly scaled objects. Camera trajectories scan rooms in randomized
visitation orders using mesh-based A* planning (Hart et al., 1968) and B´ezier smoothing. Multi-
ple trajectories diversify observation histories, while Cycles (Blender Foundation, 2026) rendering
varies floor/ceiling textures and HDRI lighting. Trajectory construction is detailed in Appendix A.
Real sequences use ScanNet (Dai et al., 2017), ScanNet++ (Yeshwanth et al., 2023), and ARK-
itScenes (Baruch et al., 2021) videos, camera information, and 3D annotations. Both sources share
the memory and QA pipeline; simulation additionally renders action-conditioned views with scene
geometry, appearance, and imaging settings fixed within each interaction.
Unified Metadata and Temporal Evidence Alignment.
We standardize categories, units, and co-
ordinates across five metadata groups: temporal frame/time mappings, camera intrinsics and poses,
object identities and geometry, visibility annotations and image-space measurements, and scene ge-
ometry and occupancy. Timestamps align projected objects and source visibility annotations with
observations; field definitions appear in Appendix A.2.
Visibility indicators, projected-box occupancy, framing completeness, and visible-pixel fractions
remain distinct. Initial simulated streams use source visibility and clipped box projections; ac-
tion views additionally provide object masks. Projected occupancy measures image extent, not
unoccluded surface area (Appendix A.2). At question time t, inputs contain only the causal prefix
O≤t = {oi : ti ≤t}; action observations enter after their commands.
3.2
MEMORY AND SPATIAL QA SUPERVISION
Incremental memory targets.
At 1 FPS, observations form five-second write windows. Memory
targets contain timestamp-linked frame references, per-frame category counts, and optional image-
plane relations. Visibility selects observed instances; projected positions on a 3 × 3 grid support
unambiguous directional relations. Records describe observed content, not a complete scene graph;
empty frames and final partial windows are retained.
Per-frame counts enumerate visible instances of each category; historical distinct-instance answers
deduplicate sightings across the causal prefix using offline instance identities, which are excluded
from model-visible memory (Appendix A).
Questions and evidence requirements.
We select a time and template, bind eligible referents,
compute the answer, and attach evidence.
Object/camera metadata supplies distances, dimen-
sions, and relative directions; temporal/visibility metadata supplies appearances, order, counts, and
changes. Room-area questions require floor polygons and coverage checks. Candidates must satisfy
visibility, referent-uniqueness, and answer-separation criteria.

Current QA uses the current observation or a specified recent window. Memory QA requires ear-
lier appearances, previously observed instances not all currently visible, or historical relations; direct
answering is allowed when this evidence remains in context. LLM rewriting varies wording while
preserving referents, temporal constraints, and annotation-derived answers. Template calculations
and examples appear in Appendix A.
Retrieval supervision.
Historical evidence determines query categories, optional time ranges, and
image requests. The deterministic router applies inference-time retrieval rules to constructed mem-
ory, yielding records and optional historical frames. Requests, responses, and answers form super-
vised traces; private instance-level checks exclude traces without sufficient evidence within budget
without altering router outputs (Appendix C).
3.3
MULTI-ROUND ACTION EVIDENCE CONSTRUCTION
Dedicated simulation rendering supplies action supervision. We bind identifiable targets and com-
pute fixed answers: size is the longest physical bounding-box side, and distance is the Euclidean
distance between 3D centers. Scene, targets, question, and answer remain unchanged, so explo-
ration changes evidence rather than the task.
Discrete atomic actions.
Five parameter-free commands translate forward, left, or right by 0.5 m
in the current camera’s horizontal frame, or rotate left/right by 45◦. Translation preserves orien-
tation; rotation preserves position. The executor fixes magnitudes; supervision uses the model’s
commands. Collision and clearance checks precede rendering each admissible resulting state.
Evidence-based sequence selection.
Joint target support is the minimum image-occupancy score
across required objects, ensuring evidence for both targets in pairwise questions. Endpoints must
satisfy occupancy and framing thresholds and exceed the best pre-question joint support by both
relative and absolute margins. We distinguish acquiring historically missing adequate views from
improving existing ones; measurement definitions and selection thresholds are in Appendix A.
We execute and render up to three admissible actions sequentially, retaining the earliest endpoint
meeting these criteria. Intermediate actions may reposition the camera without immediate gain.
Each demonstration stores the causal prefix, fixed question, command–observation pairs, and an-
swer. Counterfactual optimization additionally uses rendered alternative outcomes; demonstration
thresholds and RL rewards are separately defined in Appendices A and D.2.
Streaming Assembly and Quality Control.
Across all task types, observations, memory writes,
questions, commands, and tool results are assembled chronologically. Validation checks media,
temporal/object references, answers, duplicates, command–observation alignment, budgets, and
predecessor-state continuity. Missing evidence, failed checks, or excessive token length exclude a
sample; construction metadata and private labels remain separate from public events (Appendix A).
The MemAct-data contains approximately 1M examples, all for training, while MemAct-bench
contains 20,000 main QA pairs covering current understanding, historical evidence use, and ac-
tive exploration, plus 2,000 separate Timing questions. Training-data composition and action-length
distributions are in Appendix B, with construction thresholds in Appendix A.

4.2
INCREMENTAL MEMORY WRITING AND RETRIEVAL
To preserve history beyond visual-cache eviction, MemAct writes increments ∆Mt every five sec-
onds: per-frame categories, counts, frame references, and optional image-plane relations. The up-
date Mt = Update(Mt−5, ∆Mt) validates structure and temporal references without semantic
correction; storage and retry rules appear in Appendix C.
Structured records locate historical evidence; retrieved frames recover visual detail absent from
those records. A use memory request specifies categories, an optional time range, and image
requirements, returning matching records, relations, and optional frames to shared context. Each call
returns at most two images, with four distinct historical images per question; filtering and pagination
follow Appendix C.
4.3
EVIDENCE SELECTION AND MULTI-ROUND ACTION
Memory recovers past evidence; camera actions acquire views missing from retained observations.
MemAct answers directly when evidence suffices, including historical QA; otherwise, it retrieves or
selects one of five camera commands with executor-fixed magnitudes (Section 3.3).
A retrieval or camera command uk and result zk yield hk+1 = Append(hk, uk, zk), informing
subsequent decisions. Successive camera actions build on preceding states to improve evidence,
with at most three attempts and an independent four-call retrieval budget per question. Answering
terminates interaction; action-budget exhaustion requests a final answer. Action views remain in
question context without automatic memory writes; the original stream resumes after exploration.
Figure 4 illustrates current-view QA, memory-based last-observation QA, and three-action view
improvement; Appendix E adds QA and memory-write examples.

5.1
EXPERIMENTAL SETUP
We compare closed-/open-source general-purpose VLMs, spatial and streaming models, and
uniform-option, modal-answer-content, and modal-option-letter baselines. Models include GPT-
6 Astra (OpenAI, 2026), Gemini-3.8-Flash (Google DeepMind, 2026), Qwen3.5 (Qwen Team,
2026a), Qwen3.8-27B (Qwen Team, 2026b), InternVL3.5 (Wang et al., 2025a), VLM-3R (Fan et al.,
2025), Cambrian-S (Yang et al., 2025a), StreamingVLM (Xu et al., 2025), and Stream3D-VLM (Yu
et al., 2026). We train MemAct on our dataset and VSI-590K (Yang et al., 2025a). At each decision,
offline models receive 32 uniformly sampled frames from the available prefix; streaming models
observe causally at 1 FPS. Multiple-choice and numerical questions use accuracy (ACC) and mean
relative accuracy (MRA), respectively, following VSI-Bench (Yang et al., 2024a). Overall QA pools
Current, Memory, and Action across domains by question count (13,134 multiple-choice; 6,866 nu-
merical), scoring multi-turn questions per turn. Action is simulation-only, with all models using the
same discrete interface and attempt budget and receiving action observations before answering.
Timing uses a separate 2,000-question set balanced across domains. Questions precede evidence;
models observe at 1 FPS and wait or answer without memory/action tools. The first answer is final
and on time within the inclusive five-second window from the first evidence-sufficient checkpoint.
We report on-time rate (T), joint timing-and-answer accuracy (JA), and timing-gated MRA (JM),
averaged over applicable questions (Appendix D.4).
Latency spans image/context readiness to complete answer output, excluding frame acquisition,
observation maintenance, memory operations, action execution/rendering, and network/queueing
delays. Overall latency averages the two domains, each with 10,000 QA turns (Appendix D.3).

5.3
ABLATION STUDIES
Memory Ablations.
Table 2 ablates memory content, retention, and write frequency. Full mem-
ory improves ACC/MRA over no explicit memory by 13.59/15.48 points; ground-truth memory
adds another 2.66/3.34 points, indicating room for better memory construction. Historical RGB
contributes most: removing it costs 3.19/4.00 ACC/MRA points. Counts mainly benefit numerical
answers, while relations yield smaller ACC gains.
Extending retention from 10 seconds to full history consistently raises ACC/MRA to 68.11/67.72,
supporting evidence use beyond recent observations. More frequent writes do not consistently help:
three-second intervals maximize ACC, but our five-second interval matches MRA with only 0.02
points lower ACC and fewer writes; ten-second intervals reduce both metrics.
Action Ablations.
Table 3 compares training, rewards, and budgets using common evidence-gain
metrics and mean camera-action attempts, including invalid attempts. Cumulative-return optimiza-
tion adds 5.36/6.87 ACC/MRA points over SFT-only training and reduces mean attempts from 2.19
to 2.02. GRPO (Shao et al., 2024) achieves comparable performance. Reward ablations share termi-
nal answer rewards, action costs, and cumulative returns. Framing adds 1.16/3.48 ACC/MRA points
over pixel visibility alone; joint target evidence adds 3.26/1.92 points, supporting complete views
and balanced evidence for relational questions. Replacing current-view gains with gains over the
best historical view adds 2.47/3.71 points and raises the effective gain rate from 58.07% to 71.14%,
encouraging acquisition of new evidence. Raising the action budget from one to three attempts adds
3.67/5.48 ACC/MRA points, supporting multi-step exploration.

A
DATASET CONSTRUCTION DETAILS
This section details how observations are converted into supervision for memory writing, spatial
question answering, and camera actions. We first establish a shared temporal representation, then
describe target construction and filtering, and finally specify the action space and multi-step trajec-
tories. The question catalog provides examples and construction rules for individual templates.
A.1
OBSERVATION PREPARATION AND ALIGNMENT
Simulation episodes use existing 3D-FRONT (Fu et al., 2021) layouts and assets. We remove objects
with conspicuous interpenetration or erroneous scale while preserving the remaining scene structure.
Scanning trajectories connect geometric centers and selected centers of maximal inscribed circles in
randomized order, with the camera oriented toward the room interior. A* (Hart et al., 1968) plans
paths on a mesh-derived occupancy map over the camera’s relevant height range, and B´ezier curves
smooth the resulting paths. Multiple trajectories provide different visitation orders and observation
histories for each layout. Floor and ceiling textures and randomly selected HDRI environments vary
appearance, and Cycles (Blender Foundation, 2026) renders the RGB observations and auxiliary
visibility annotations.
Real observations originate from ScanNet (Dai et al., 2017), ScanNet++ (Yeshwanth et al., 2023),
and ARKitScenes (Baruch et al., 2021) videos. Frames are aligned with camera poses and source
3D annotations through physical timestamps. Coordinate transformations and projection associate
annotated objects with individual observations. Both branches provide time-ordered RGB frames,
category labels, instance correspondences, geometry, and per-frame visibility. We sample observa-
tions at 1 Hz and express geometric distances in meters. Per-frame visibility follows the source
annotations.
Pixel-level measurements are used where rendered masks are available; projected
bounding-box area is separately identified when used as an evidence proxy.
For a question at time t, historical evidence is selected from the observation prefix O≤t. An action-
generated observation becomes available only after the corresponding command is executed. Offline
geometry and instance identifiers determine supervision, whereas the model receives RGB observa-
tions, timestamps, retained context, and returned tool content. Each example records its question
time, evidence-frame references, answer, and construction provenance.
A.2
METADATA AND EVIDENCE MEASUREMENTS
Temporal metadata maps frame references to timestamps. Camera metadata contains intrinsics and
poses; object metadata supplies persistent identities, categories, 3D centers, dimensions, and avail-
able meshes or boxes. Scene metadata supplies geometry, occupancy, and floor polygons. Visibility
metadata links these records to individual observations. Distances use meters, image fractions are
dimensionless, and each evidence measurement records its provenance.

A.4
SPATIAL QA CONSTRUCTION
Each QA example is constructed by selecting a causal observation prefix, binding its referents,
computing an answer from aligned annotations, checking evidence and ambiguity conditions, and
instantiating a question template. Multiple-choice questions use distinct semantic alternatives and
retain the mapping between option letters and answers. Numeric questions specify their units. All
QA text undergoes one LLM polishing pass to diversify phrasing while preserving referents, tempo-
ral constraints, units, option meanings, and annotation-derived answers.
17


Preprint
Current QA.
Current questions use the latest observation or an explicitly specified recent window,
with a default duration of five seconds. Camera-to-object and object-to-object distances use 3D cen-
ters. Trajectory length sums consecutive camera translations, endpoint displacement measures the
distance between the initial and final positions, and orientation change measures the net endpoint ro-
tation. Referents must be uniquely identifiable under the question wording. Nearest-camera queries
require a minimum 0.15 m separation between the two closest candidates; designated-object nearest-
neighbor queries require 0.40 m. Appearance and disappearance questions require a unique category
change between the specified observations.
Memory QA.
Memory questions require evidence preceding the current window. First and last
appearances are computed over the full causal prefix, historical counts use instance-set unions, and
historical relationships are evaluated at the referenced frame. Appearance-order questions require
successive first-observation times to differ by at least two seconds. Historical-neighbor questions
bind a uniquely observed target that is absent from the current view and select neighbors among ob-
jects co-visible at the specified historical time. These evidence conditions define the question family;
the model can answer directly when its retained context already contains the required information.
Chained questions and geometric examples.
For linked questions, the first turn establishes an
object or category and subsequent turns retain that referent. These linked QA turns are distinct
from multiple camera actions taken to answer a single question. Each turn is associated with its
own arrival time and evidence prefix. Height questions compare vertical extent rather than elevation
above the floor, with a 0.30 m margin between the two tallest candidates. Room-area questions use
the room’s floor polygon, including floor beneath furniture, and require at least eight observations,
90% boundary-angular coverage, and a viewing-direction span of at least 150◦.
A construction example.
Consider a nearest-object question with visible object-center distances
of 1.0, 1.4, and 2.1 m. The first object supplies the answer because its 0.4 m lead exceeds the
0.15 m ambiguity margin. Replacing the second distance with 1.08 m rejects the example. For a
first-appearance question, the answer is the earliest visible frame in the complete prefix, and the
example is assigned to Memory QA when that evidence precedes the current window.
A.5
SELECTING QUESTION TIMES AND OBJECT REFERENTS
Construction operates on aligned frame records rather than RGB alone. Each record links a times-
tamp and image to its camera pose, visible-instance set, and category labels. Object records sup-
ply persistent instance identifiers, 3D centers, and the geometric fields required by each template;
image-plane relations additionally use projected positions, and room-area questions use floor poly-
gons. These annotations select candidates and compute labels offline. Public questions identify
objects through category names, explicit nearest-instance qualifiers, or image regions, without ex-
posing instance identifiers or geometric answers.
Candidate times and evidence windows.
We enumerate candidate times on the sampled ob-
servation sequence and apply template-specific temporal conditions before constructing a ques-
tion. Single-view questions use the question frame; motion and visibility-change questions require
the specified earlier endpoint. Nearest-neighbor, fixed-reference relation, and height-comparison
templates enumerate interior frames. Last-seen, historical coappearance, historical direction, and
appearance-order templates are proposed every five sampled frames starting at index ten. Memory
evidence must belong to the available prefix and be covered by completed memory writes. Room-
area candidates are proposed when a continuous within-room observation run meets the coverage
conditions. A frame that does not satisfy a template’s conditions produces no example for that
template.
Object eligibility and combinations.
For nearest-neighbor, fixed-reference relation, and height-
comparison templates, candidate objects are visible at the question frame and its two adjacent
frames, and each selected category has exactly one visible instance at the question frame. The
adjacent-frame test selects stable observations offline; the following frame is not included in the
question’s model input or used to compute its geometric answer.

Historical selection and memory verification.
The last-seen template selects a category absent
at the question frame whose latest occurrence is at least five frame indices earlier. That historical

stated in the question. Coappearance distractors are absent from the referenced frame. Direction
questions require unique category instances and a same-row or same-column grid relation. First-

apart, with the latest first sighting at least five frame indices before the question. We replay the
corresponding teacher memory writes and retrieval requests, reconstruct the answer from returned
records or relations, and require agreement with the annotation-derived label. Direction examples
additionally require the referenced image to be retrievable within the image budget.
Room evidence and retained records.
Room-area construction uses simulation episodes with
a valid floor polygon and unambiguous camera-to-room assignment. Leaving the assigned room
resets the observation run. Each polygon edge contributes eight boundary samples; coverage counts
samples falling within the horizontal viewing angle of at least one observation in the run. We
require eight observations, 90% angular boundary coverage, and a 150◦heading span. This is a
geometric coverage proxy rather than a wall-pixel visibility test. Each retained QA records its
template, question time, evidence-frame references, bound objects where applicable, answer, and
source-scene provenance. Missing evidence images and failed template checks are excluded before
serialization.

and geometric checks select demonstration sequences; alternative action outcomes are rendered and
recorded separately for counterfactual optimization.

Discrete action interface and multi-step interaction.
The action interface consists of five com-
mands: forward, leftward, and rightward translation by 0.5 m, and left and right rotation by 45◦.
Translation follows the current camera’s horizontal coordinate frame and preserves orientation; ro-
tation preserves position. The model selects a command, and the runtime assigns its fixed magnitude.
Each returned observation is associated with the resulting camera state. Interactions allow at most
three action attempts, each continuing from its predecessor state and producing a specifically ren-
dered observation. Demonstrations terminate at the earliest endpoint satisfying the unified quality
and gain criteria above. Intermediate views need not satisfy the endpoint thresholds or improve
evidence monotonically, allowing preparatory actions.
Geometric checks and serialization.
For each segment, a mesh-based check rejects a surface
intersection along the straight camera-center connection. Positions sampled at intervals no greater
than 0.025 m require at least 0.125 m surface clearance and support within 2 m below. The serialized
example contains the causal prefix, unchanged question, ordered command–image pairs, and final
answer; future trajectory images enter the model context only after their corresponding commands.
Duplicate candidates sharing the source trajectory, bound target or pair, endpoint, and template are
removed. Distance-range and proximity candidates share the same geometric quantity. Identical
serialized sequences are deduplicated across these template labels, and the final release retains the
distance-range label.

Demonstration endpoint thresholds do not filter these alternatives: valid actions with little or neg-

recorded separately. Branch validation distinguishes missing rendered outcomes (coverage errors)
from physically invalid actions, which preserve the observation and consume an attempt. RL re-

A.7
ASSEMBLY AND QUALITY CONTROL
We assemble observations, memory targets, questions, and tool outcomes into causally ordered train-
ing sequences. The training release contains all retained QA examples; the main test and Timing
sets are separate evaluation collections. Validation checks timestamps, frame references, referent
consistency, answer computations, duplicate semantic questions, tool-image correspondence, and
interaction budgets. Examples with missing required evidence, failed constraints, or excessive se-
quence length are excluded. Public model inputs and private annotation fields are stored separately.

C
MEMORY ROUTER DETAILS
The memory router maintains model-written records and retrieves historical evidence through deter-
ministic rules. Its responsibilities are structural validation, persistent storage, category/time filtering,
and budgeted image return. The shared model supplies the semantic content of memory writes and
formulates retrieval requests.
C.1
WRITING AND STORAGE
A memory write uses the fields type, observations, and relations. Observation entries
contain a frame reference and a list of category–count pairs. The router requires contiguous half-
open windows [ts, te), exactly one record per supplied frame, normalized lowercase category strings,
positive integer counts, and valid relation endpoints. Empty object lists represent frames without
visible objects. A valid write is stored with its frame/time mapping and a payload receipt. Repeating
an identical write returns already stored; a different payload for the same window is rejected
as a conflicting retry. Semantic predictions are stored as generated by the model.
C.2
QUERIES, PAGINATION, AND IMAGES
Each question allows at most four memory-retrieval calls. A retrieval request specifies categories,
an optional time range, and whether images are required. Category matching returns the union
of matching records, with an additional co-visibility indicator for records containing all requested
categories; an empty category list selects all categories. Results are ordered by time and paginated at
eight records per page. A continuation cursor is bound to the original query and its record snapshot.
When images are requested, the router selects one representative per contiguous matching run, pre-
ferring co-visible records and the timestamp nearest their midpoint. Additional candidates are or-
dered by the summed counts of requested categories. Each call returns at most two images, with
at most four distinct historical images per question. Returned images remain in context and are not
resent. New questions reset pagination and image budgets; textual frame references remain available
after the image budget is exhausted. These limits concern retrieved history, not action observations
or the entire context.
Relations contain a frame, a predicate, and subject/object endpoints specified by category and image-
grid region. Query time ranges are half-open. Category filtering selects frame records, and the
response includes all relations attached to frames in the returned text page or image list. It does not
independently filter relation endpoints by query category.

D
TRAINING AND EVALUATION DETAILS
Training first learns the shared output protocol through supervised fine-tuning and then optimizes
action decisions using cumulative continuation returns. Both stages use the same vision–language
model and structured outputs. This section specifies optimization, causal rollout construction, and
answer scoring.
D.1
SHARED CONFIGURATION AND SUPERVISED FINE-TUNING
We use Qwen3.5-4B and Qwen3.5-9B (Qwen Team, 2026a) with LoRA (Hu et al., 2021) applied
to the query and value projections, using rank eight, scaling factor sixteen, and zero dropout. Base-
model parameters, including the visual encoder, are frozen. We use our dataset together with VSI-
590K (Yang et al., 2025a) for SFT. Both stages use AdamW (Loshchilov & Hutter, 2017) with a
learning rate of 10−5 and gradient clipping at 1.0. Training uses eight GPUs, one training item per
GPU per microbatch, and eight gradient-accumulation steps, giving 64 items per update. SFT items
are serialized sequences; action-optimization items are decision histories whose candidate rollouts
are evaluated internally. Each serialized training sequence is limited to 180,000 tokens, including
text, visual tokens, and supervised assistant outputs. Sequences exceeding this budget are discarded
without truncation or splitting.
SFT sequences preserve the order of observations, memory triggers, questions, and tool results. Only
assistant outputs contribute to the token loss: memory records, retrieval requests, camera commands,
and answers. Prompt and tool-result tokens provide context. The loss is averaged over supervised
assistant tokens within each sequence and then over the effective batch. Linked questions retain
their original referents and causal context.

Main QA aggregation and latency.
The main evaluation contains 10,000 QA turns from each
domain. Overall ACC pools the 13,134 multiple-choice turns, and Overall MRA pools the 6,866

The overall mean uses all 20,000 main QA turns, equivalent to averaging the two domain means
with equal weights.
