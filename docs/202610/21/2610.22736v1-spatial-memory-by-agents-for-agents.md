## 摘要
空间记忆使机器人能够复用过去的观测，用于定位、导航和问答。设计此类记忆需要共同决定保留什么以及如何检索，以满足多样化的语义、度量和时间需求。我们研究编码智能体能否通过迭代实现与评估来自动化这一设计过程。在固定的开发预算下，设计智能体（Designer Agent）利用固定查询智能体（Query Agent）的反馈，编写并修订用于记忆构建与检索的代码。所得实现在从留出观测历史构建记忆之前被冻结，且无法访问下游问题，并使用同一查询智能体在五个互补任务轨道上进行评估。在三次独立的设计搜索中，Codex / GPT-6 Astra 在等权五轨道得分上平均为 44.23，而 ReMEmbR——支持全部五个轨道的最强评估基线——为 29.32，相对提升 50.9%。定性分析将性能差异与证据保留和检索联系起来，同时识别出 grounding 和证据使用方面的失败。这些结果展示了编码智能体自动化空间记忆设计的潜力，同时揭示了性能与计算成本方面依赖任务的权衡。项目页面：https://ba-fa-3344.github.io/。

## Abstract
Spatial memory enables robots to reuse past observations for localization, navigation, and question answering. Designing such memory involves jointly deciding what to retain and how to retrieve it for diverse semantic, metric, and temporal needs. We investigate whether coding agents can automate this design process through iterative implementation and evaluation. Under a fixed development budget, a Designer Agent writes and revises code for memory construction and retrieval using feedback from a fixed Query Agent. The resulting implementations are frozen before building memories from held-out observation histories, without access to downstream questions, and evaluated across five complementary task tracks using the same Query Agent. Across three independent design searches, Codex / GPT-6 Astra averages 44.23 on the equally weighted five-track score, versus 29.32 for ReMEmbR, the strongest evaluated baseline supporting all five tracks, a 50.9% relative improvement. Qualitative analysis relates performance differences to evidence retention and retrieval, while identifying grounding and evidence-use failures. These results demonstrate the potential of coding agents to automate spatial memory design, while revealing task-dependent trade-offs in performance and computational cost. ## 1. 核心问题与研究动机

- **背景**：机器人空间记忆需要复用历史观测，以回答探索时未知的问题（物体在哪、房间什么样、何时见过某物），这些查询同时要求**语义、度量、时间**三类互补证据。
- **现有系统的分歧**：ReMEmbR 存储“带位姿与时戳的 caption”，ConceptGraphs 构建物体中心图，DAAAM 维护时序物体/地点历史，FARM 通过空间关系检索——各自只优化部分查询类型。
- **核心矛盾**：记忆设计是一个**高度耦合的大空间**（感知模型、关联策略、嵌入、检索工具），"保留什么"与"如何让下游智能体检索到"必须联合决策；手工反复实现-评估-修改成本高昂，且一种查询的记忆往往丢失另一类查询所需信息。
- **研究问题**：给定可复用组件池、公开反馈和固定开发预算，**编码智能体能否为另一个智能体自动设计出跨任务可用的空间记忆？** 即 "Spatial Memory by Agents, for Agents"。

## 2. 方法论

### 2.1 总体框架：设计–构建–查询三阶段分离
- 系统被形式化为 $s=(B_s, T_s, p_s)$：记忆构建器 $B_s$（产生 $M_s=B_s(O)$）、检索工具集 $T_s$、工具使用说明 $p_s$。

### 2.2 Designer 协议（核心机制）
- 从"未实现的 builder + 共享任务说明/指标/模块池/公开数据"出发，Designer 可编辑 builder、检索工具、工具说明；**评估器与 Query Agent 内核不可改**。
- 循环：**实现 → 评估 → 检查 → 保留/回退 → 修订**；可查看公开参考答案、记忆包、逐查询工具轨迹，并记录保留/回退理由。
- 24 小时固定预算覆盖编码、API 等待、构建与评估；选择仅使用公开反馈。

### 2.3 共享模块池
- YOLOE（检测）、FastSAM（分割）、OpenCLIP / DINOv3（视觉特征）、Qwen3.5-4B（caption）、Qwen3-VL-Embedding-2B（多模态嵌入）；偏好紧凑模块与 4B 消费级模型（量化后可在 Jetson Orin 上推理）。

### 2.4 资源约束的目标函数
- 资源调整后的公开分：
$$J_{\text{report}}(s)=\frac{1}{5}\sum_{t=1}^{5}u_t(s)-C_{\text{resource}}(s)$$
- 惩罚项：$C_{\text{resource}}(s)=0.2\,[m_s/m_0-1]_+ + 0.5\min\{1,[b_s/b_0-1]_+\}$，其中 $m_0=50\times10^6$ 字节、$b_0=0.2$ s/frame；包大小与构建时间在预算内不罚，时间惩罚上限 0.5；**查询延迟不惩罚**。

### 2.5 冻结的构建–打包–查询评测
- 实现冻结后才在**留出历史**上构建记忆，构建时**不接触任何问题或参考答案**；同一记忆包跨五轨复用。
