## 摘要
空间推理要求模型判断物体在三维空间中的位置、它们之间的相互关系以及它们如何运动。智能体式视觉语言模型（agentic VLMs）最近通过让模型使用三维感知工具主动收集证据，而非单次作答，在此类任务上取得了大幅提升。即便如此，在许多问题上，工具返回了正确证据，模型却仍未得到正确答案：模型与工具之间的缺口——即原始读数转化为可用结论之处——仍未被填补。我们提出 S-Agent 2.0，一种空间推理智能体，它为现成的通用编码智能体配备命令行感知工具包，并围绕一个原则设计接口：帮助 VLM 闭合证据环路：获取场景证据、将其记忆在持久场景记忆中，并用通俗的空间语言解释每个读数。该设计保留了编码智能体的全部灵活性，且其处理的每个读数始终以工具的几何信息为依据。在 MMSI-Bench 和 ReVSI 上，该工具包使强开源模型 Qwen3.8-27B 相比同一智能体无工具时分别提升 +13.9 和 +20.5 分，使强闭源模型 Gemini-3.8-Flash 分别提升 +11.2 和 +9.6 分。在开源骨干模型上，S-Agent 2.0 在 MMSI-Bench 上达到 66.5，在 ReVSI 上达到 82.3，超过同一骨干上的专用系统 SpatialClaw（62.6 和 74.5）；搭配 Gemini-3.8-Flash 时达到 74.1 和 90.5，而后者为 67.0 和 79.7。随着骨干模型能力增强，两种工具带来的增益均会缩小，但 SpatialClaw 在 ReVSI 上的增益缩小幅度大得多，从 +13.2 降至 +2.7，而我们的方法保持在 +9.6。S-Agent 2.0 还可跨不同的通用编码智能体框架（如 Codex 和 Claude Code）工作。

## Abstract
Spatial reasoning asks a model to work out where objects are in 3D space, how they relate to one another, and how they move. Agentic VLMs have recently brought large improvements on such tasks by letting the model actively gather evidence with 3D perception tools instead of answering in a single pass. Even so, on many questions the tools return the right evidence and the model still does not arrive at the correct answer: the gap between model and tools, where raw readings become usable conclusions, is left unfilled. We present S-Agent 2.0, a spatial reasoning agent that equips an off-the-shelf general coding agent with a command-line perception toolkit, and we design the interface around one principle: help the VLM close the evidence loop: acquire scene evidence, remember it in a persistent scene memory, and interpret each reading in plain spatial language. This design keeps the full flexibility of a coding agent, and every reading it acts on stays grounded in the tools' geometry. On MMSI-Bench and ReVSI, the toolkit improves a strong open-source model, Qwen3.8-27B, by +13.9 and +20.5 points over the same agent without tools, and a strong closed-source model, Gemini-3.8-Flash, by +11.2 and +9.6 points. With the open backbone S-Agent 2.0 reaches 66.5 on MMSI-Bench and 82.3 on ReVSI, ahead of the specialized system SpatialClaw on the same backbone (62.6 and 74.5), and with Gemini-3.8-Flash it reaches 74.1 and 90.5 against its 67.0 and 79.7. Both tool gains shrink as the backbone grows more capable, but SpatialClaw's shrinks far more on ReVSI, from +13.2 to +2.7, while ours stays at +9.6. S-Agent 2.0 also works across different general coding agent harnesses, such as Codex and Claude Code.

## 一、核心问题与整体含义（研究动机与背景）

- **背景**：空间推理要求模型判断物体在三维空间中的位置、相互关系及运动方式。近年来，智能体式视觉语言模型（agentic VLM）通过调用三维感知工具主动收集证据，而非单次前向作答，在 MMSI-Bench、ReVSI 等基准上取得显著进展。
- **核心痛点——"证据回路未闭合"**：作者观察到，在许多问题上**工具返回了正确证据，模型却仍答错**。作者将失败归为两类：
  - **误读读数**：模型把测对的旋转方向符号弄反，或在错误的坐标系 / 错误的方向语义下理解正确数值。
  - **证据未进入答案**：测量结果留在工作区，模型却"用眼睛看图片"作答；或正确读数被无关理由丢弃。
- **对现有系统的诊断**：以 SpatialClaw 为代表的专用系统几乎把全部设计精力投入**证据获取**（更丰富的感知与几何工具库），却把**记忆**与**解释**两步留给模型。而真正的断点恰恰在"原始读数 → 可用结论"这一环。
- **整体含义**：论文提出闭合证据回路需要三条要求——(i) 工具测量与模型自身感知进入**同一场景**；(ii) 已获取证据由**持久记忆**保存，直到答案写出；(iii) 读数以**问题所用的空间语言**到达模型。

## 二、方法论

### 2.1 核心思想

- 不设计专用控制器，而是**直接复用现成的通用编码智能体**（OpenHands / Codex / Claude Code）作为空间推理智能体，把设计精力全部投入到**命令行感知工具包**的接口设计上。
- 编码智能体的两个固有习惯被直接利用：①"看图片"是流中的普通文件操作，模型自身感知与工具读数在同一对话中交错；②"检查—修正"是本能反射，可把模型感知与工具感知在读数之前对齐。

### 2.2 系统组成（三部分）

- **规划/执行器 π**：通用编码智能体，接收固定指令 u（工具包教程 + 推荐工作流：确定所需证据 → 通过工具获取 → 检查输出 → 依据读数作答）。
- **命令行感知工具包 T**：一条可执行程序 `perception.py`，所有命令读写场景记忆，回复为 stdout 上的 JSON，渲染图像写入磁盘供智能体查看。
- **持久场景记忆 S**：`S = ⟨I, P, {(ν_i, g_i)}⟩`，其中 `g_i = ⟨p_i, E_i, T_i⟩`，包含原始帧 I、重力对齐的融合度量点云 P、命名实例注册表（名字 ν、xyz 位置 p、范围 E、6-DoF 位姿 T）。

### 2.3 形式化流程

- 推理步 t 的策略：`(z_t, a_t) ~ π(· | u, q, z_<t, a_<t, o_<t)`，动作空间 `A_gen ∪ A_perc`。
- 感知动作语义：`(o_perc, S_{t+1}) = τ(x_t; S_t)`，`τ ∈ T_tool ∪ T_model`。
- 读数函数族：`R_τ(ν_1, …, ν_k; S_t)`，从存储几何**闭式**计算（距离、方向、仰角、运动、罗盘方位等），每次调用都从记忆重新推导，模型只需记住实例名。

### 2.4 三项关键设计

- **按能力划分感知（T_tool vs T_model）**：
  - `T_tool`（测量端）：`recon` 用 Depth Anything 3 + GeoCalib + π³mos 融合度量点云并注册相机；`segment` 用 SAM 3 按模型给的文本提示分割并注册实例。
  - `T_model`（语义端）：`add_instance` 让模型把"它识别到的物体"或"问题想象出的观察者"注册进同一几何框架（支持从地图像素、原图像素或相机位置初始化，用 `--facing/--primary/--secondary` 指定朝向）；`drop` 让模型删除工具误注册的实例（如反射上的掩膜）。
- **环境侧持久记忆**：不由模型上下文承载中间结果，而由工具包写入场景记忆，后续按名字查询，避免长转录中的信息丢失。
- **"到达即解释"的语言表面**：每条命令把完整输出 m 相对于 S 蒸馏为 `o_perc = c_τ(m; S)`，结构固定为"带单位的数值字段 + 一句结论句"；结论句**点名实体、声明坐标系（重力对齐/相机/图像平面）、并直接落到答案使用的普通空间词汇**（如 "front-left"、"0.41 m RIGHT · 0.92 m TOWARD cam."）。完整几何仍留在磁盘上的 m 中，模型需要时可再读。

### 2.5 证据回路

`q → E（模型决定所需证据）→ x（调用参数）→ m（磁盘完整输出）→ o_perc（解释后回复）→ answer`，其中虚线回边表示模型把每次回复读回证据 E 并作为下一次调用的参数——回路由此闭合。

## 七、局限与待改进之处

- **对感知后端质量敏感**：度量点云、重力方向、分割掩膜均来自冻结的现成模型，后端误差会直接进入“闭式读数”，论文未报告后端噪声对最终答案的传播分析。
- **成本未量化**：每个 episode 至少一次在线重建 + 多次分割，属于较重的推理开销；论文未给出延迟、显存或 token 消耗的对比，因而难以评估相对“单次前向 VLM”的性价比。
- **统计稳健性不足**：未报告多次运行的方差或置信区间，单次运行的结果差异（尤其 1–2 分级别的差距）难以判断显著性。
- **基线复现范围有限**：部分强闭源基线引用外部报告数字，评测协议（提示词、采样参数、图像分辨率）未必完全对齐。
- **定性展示的选择性**：案例均为作者挑选的对比样本，缺少对“本文答错而基线答对”情形的对称分析。
- **通用编码智能体的固有开销**：把空间推理交给通用 agent，意味着承担其自身的规划冗余与无关动作，论文未讨论如何抑制这类额外成本。

## 八、可借鉴的设计启示

- **“接口即方法”**：在不改模型、不训练的前提下，仅通过重塑工具输出的**语言表面**（单位、坐标系、实体命名、结论句）即可获得两位数增益，说明 agentic 系统的性能瓶颈常位于接口层而非能力层。
- **把中间状态放到环境里，而不是上下文里**：以环境侧持久记忆替代长转录承载几何量，模型只记“名字”，按名查询，天然规避长上下文的信息衰减。
- **允许模型往工具的世界里写**：`add_instance` / `drop` 让模型自身的语义判断（“这是同一把椅子”“问题想象的观察者在此处”）与工具测量共享同一坐标框架，是闭合回路的关键机制，而非附属功能。
- **利用通用 agent 的既有习惯**：把“看图”实现为普通文件操作、把“检查—修正”留给模型本能，比自建专用控制器更省设计成本且更易迁移（三种框架均可直接复用）。
- **可调试性作为一等目标**：逐字命令记录 + 磁盘上的完整几何输出，使每一次错误都能追溯到“哪一步读数、哪一个坐标系、哪一个实例名”，这对空间推理这类错误隐蔽的任务尤为重要。
