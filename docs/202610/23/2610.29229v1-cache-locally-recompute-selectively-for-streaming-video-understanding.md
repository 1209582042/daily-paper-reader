## 摘要
流式视频理解（SVU）要求视频-LLM在持续处理输入视频的同时，以低延迟回答用户查询。近期方法通过在空闲时间将帧预填充到KV缓存，并在查询时复用缓存的KV，来降低查询时开销。为在无界视频流上限制每帧计算量，这些方法限制了预填充期间可用的上下文。这造成了根本性的上下文不匹配：受限上下文可能遗漏正确情境化视频token所需的信息，同时仍包含与最终查询无关的信息，而该查询在预填充时未知。我们提出FrameBlend，一种简单而有效的即插即用方法，通过选择性KV重计算解决这一不匹配，且无需任何额外训练。在查询时，FrameBlend使用与查询相关的上下文重新预填充选定的视频token，并用重计算得到的KV替换其缓存KV。关键在于，这种重计算使得空闲时间预填充能够采用更短的注意力窗口，从而在提高准确率的同时大幅降低预填充开销。在三个SVU框架和五个流式及离线基准上的实验表明，准确率最高提升3.9个百分点。在RVS-Ego上，对于基于检索的框架，FrameBlend将每帧预填充FLOPs降低20%以上，并将总处理时间降低14–59%，其中包含查询时重计算的开销。这些结果表明，仅改变情境化在空闲时间与查询时间之间的分配方式，就能改善SVU的准确率-效率权衡。

## Abstract
Streaming video understanding (SVU) requires video-LLMs to process incoming video continuously while answering user queries with low latency. Recent methods reduce query-time cost by prefilling frames into KV caches during idle time and reusing the cached KVs at query time. To bound per-frame computation over unbounded video streams, these methods restrict the context available during prefill. This creates a fundamental context mismatch: the restricted context may omit information needed to properly contextualize video tokens, yet, still contain information irrelevant to the eventual query, which is unknown during prefill. We propose FrameBlend, a simple yet effective plug-and-play method to address this mismatch through selective KV recomputation, without requiring any additional training. At query time, FrameBlend re-prefills selected video tokens using query-relevant context and replaces their cached KVs with recomputed ones. Crucially, this recomputation enables shorter attention windows during idle-time prefill, substantially reducing prefill cost while improving accuracy. Experiments across three SVU frameworks and five streaming and offline benchmarks demonstrate accuracy gains of up to 3.9 pp. On RVS-Ego, FrameBlend reduces per-frame prefill FLOPs by over 20% and total processing time by 14-59% for retrieval-based frameworks, including the cost of query-time recomputation. These results demonstrate that a simple change in how contextualization is distributed between idle time and query time can improve the accuracy-efficiency trade-off for SVU.

## 1. 核心问题与研究动机

- **背景**：流式视频理解（SVU）要求视频-LLM 持续处理无界视频流，并在用户查询到达时低延迟作答。实时机器人、自动驾驶、监控等应用推动了对 SVU 的需求。
- **现有范式**：近期方法在“空闲时间”把到来的帧预填充进 KV 缓存，查询时直接复用缓存 KV，从而把大部分预填充计算转移到空闲期，降低查询时延。
- **关键矛盾**：为约束无界流上的每帧计算量，现有方法限制预填充上下文——或用滑动窗口只关注近期帧，或用 KV 压缩把历史压成固定大小记忆。这导致**上下文错配（context mismatch）**：
  - 受限上下文可能**遗漏**正确情境化视频 token 所需的信息（窗口外的 token 在查询时被检索到，却未在预填充时看到彼此）；
  - 同时缓存中又**保留**了与最终查询无关的信息（压缩/驱逐后残留的上下文）；
  - 而预填充时未来查询未知，无法预先决定保留什么。
- **后果**：直接复用这些未修正的 KV 会降低回答质量。
- **整体含义**：论文主张重新分配“情境化计算”在空闲期与查询期之间的比例——空闲期少做、查询期对少量关键 token 补做，即可同时改善精度与效率。

## 2. 方法论：FrameBlend

### 核心思想
- 一种**无需训练、即插即用**的方法：查询到达后，用查询相关上下文**重新预填充**一小部分选定的视频 token，并用重算 KV **覆盖**其缓存 KV。
- 关键推论：既然缺失的上下文可在查询时补回，空闲期预填充就**不必用大窗口**，可改用短注意力窗口，从而降低预填充成本，并因减少“查询无关上下文干扰”而提升精度。

### 关键技术细节
- **Step 1：重计算目标选择（QTS，查询相关 token 级选择）**
  - 设计原则：优先选对答案影响最大的高查询相关 KV；同时保证选择过程轻量，以压缩查询时延迟。
  - 与 CacheBlend 等 LLM 服务方法不同，QTS **不做查询无关的逐层顺序选择**，而是做 **token 级选择**：同一 token 在所有层统一决定是否重算，从而把固定计算预算均摊到各层、消除层间操作。
  - 具体做法：统计每个 token 在多少层被骨干框架的检索集选中（跨层“投票”/一致性），取票数最高的 Top-K token：
    - \(P = \{x_i \mid \phi(x_i) \in \mathrm{ArgTopK}(\{\phi(x_i)\})\}\)，其中 \(\phi(x_i) := \{\ell : c_i^\ell \in S^\ell\}\)；
    - 票数并列时用归一化检索分数之和打破平局。
  - 对**无查询时检索**的框架（如 HERMES）：额外做一次辅助检索前向，按查询相似度取每层 Top-M token 作为投票集；该检索只影响“重算谁”，不改变骨干原本的解码上下文。
- **Step 2：重计算与解码**
  - 选中的 token 按时间顺序**联合重预填充**通过所有 LLM 层，仅需一次前向。
  - 替换规则：\(\tilde c_i^\ell = \hat c_i^\ell\)（若 \(x_i \in P\)），否则保留 \(c_i^\ell\)；仅替换“既被选中、又原本在该层检索集中”的槽位，**不向解码上下文新增帧**，也不改动骨干检索策略。
  - 为避免重复视觉编码，空闲期把投影后的视觉 token 保留在 **CPU 内存**中。
- **短窗口预填充**
  - 窗口可缩至骨干原窗口的 **1–68%**（如 ReKV 原 15K token，可降到 196 token，约一帧）。
  - 实验显示精度随窗口先升后降，最佳窗口因基准而异，短窗口（甚至单帧）常优于长窗口，作者归因于**减少上下文干扰**。

## 3. 实验设计

- **基准（5 个）**
  - 流式：**OVO-Bench**（Real-time / Backward / Avg.）、**RVS**（RVS-Ego、RVS-Movie，开放问答，用 GPT-3.5-turbo-0125 评分）。
  - 离线：**MLVU**（官方 dev set）、**Video-MME**（无字幕）、**EgoSchema**（官方评测服务器）。
- **集成的 SVU 框架（3 个）**：ReKV（滑动窗口 + 分层检索）、LiveVLM（压缩 KV + 页级检索）、HERMES（分层压缩 KV、无查询时检索）。
- **骨干视频-LLM（2 个）**：LLaVA-OneVision-7B、Qwen2.5-VL-7B。
- **对比对象**
  - 各框架**原始版本**（同配置，仅改窗口与加重算）；
  - **CacheBlend**（同窗口、同替换策略，仅换目标选择机制，用于隔离 QTS 的作用）；
  - **离线 LLaVA-OV-7B（查询时均匀采样 64 帧全量预填充）**，用于 TTFT–精度权衡定位。
- **超参**：视频 0.5 FPS；重算预算 K = 7840 token（LLaVA-OV 约 40 帧）；窗口按“框架×基准”逐一调优。
- **效率度量**：每帧预填充 TFLOPs 与毫秒、重算耗时、TTFT、总 FLOPs、总延迟、峰值 VRAM、CPU 内存。

## 6. 主要结论与发现

- **精度**：所有“框架–基准”组合的聚合精度**持平或提升**；流式基准最高 +3.2 pp，离线最高 +3.9 pp；LLaVA-OV 上 RVS-Ego +1.3–3.1 pp、RVS-Movie +0.2–1.8 pp、OVO-Bench 平均 +0.2–1.5 pp。
- **效率**：RVS-Ego 上每帧预填充 FLOPs 降 12–26%（ReKV/LiveVLM 为 22.2–26.0%），预填充延迟降 13–61%；计入重算后总 FLOPs 降 10–23%、总延迟降 14–59%。
- **短窗口有效**：加入重算后，短窗口（可至单帧 196 token）反而优于长窗口，与 ReKV 原始“窗口越长越好”的结论相反。
- **消融**：单用短窗口或单用重算效果不稳定；二者**组合**在所有基准上取得最佳聚合精度。
- **QTS 优于 CacheBlend**：三个流式基准上精度更高、附加 TTFT 更低（如 RVS-Ego +2.26 s vs +0.76 s）。
- **规模效应**：视频越长，延迟与峰值显存收益越大。
- **权衡定位**：FrameBlend 的 TTFT 高于纯 KV 复用，但远低于查询时全量预填充，且精度更高。

## 7. 优点

- **简洁通用**：无需训练、即插即用，对现有 SVU 框架只需改窗口大小并加重算模块，工程落地成本低。
- **反直觉且有价值的洞察**：把“上下文该在何时构建”作为设计变量，证明短窗口 + 查询时补算可同时提升精度与效率。
- **QTS 设计轻量**：复用骨干已有的分层检索结果做跨层投票，避免额外查询时操作与层间顺序依赖，契合 SVU 严格延迟预算。
- **实验矩阵较完整**：跨 3 框架、2 骨干、5 基准，兼顾流式与离线，并区分空闲期/查询期成本核算。
- **对比设计规范**：与 CacheBlend 的控制变量对比、与离线全量预填充的权衡对比，均较有说服力。

## 8. 不足与局限

- **模型规模受限**：仅验证 7B 级骨干，更小/更大模型上的有效性未知。
- **窗口需人工调优**：固定窗口按框架与基准手工选择，缺乏对视频流的自适应机制，实用性受限；且调优发生在评测基准上，结果可能偏乐观。
- **查询时延迟增加**：重算使 TTFT 增至约 1 秒，对延迟要求更严的场景不友好；重算预算 K 固定，未按延迟约束动态调整。
- **额外内存开销**：需在 CPU 保存投影视觉 token（RVS-Ego 上 ReKV 达 2.36 GiB、LiveVLM 1.01 GiB、HERMES 0.25 GiB）；压缩式框架在窗口 4096 时峰值显存还略有上升（约 +0.38/+0.22 GiB）。
- **收益不一致**：部分指标小幅下降，部分基准提升幅度很小，说明“短窗口减少干扰”的解释尚未被严格验证（缺少对干扰机制的定量分析）。
- **任务覆盖有限**：仅评估视频 VQA 类任务，未涉及时序定位、多轮对话、长程推理等其他 SVU 能力。
- **效率测量范围有限**：仅在单卡 A100 上测墙钟时间，未报告多卡、不同硬件或不同批处理设置下的表现。
