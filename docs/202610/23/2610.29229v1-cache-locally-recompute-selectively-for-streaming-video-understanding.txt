## ABSTRACT 

Streaming video understanding (SVU) requires video-LLMs to process incom-ing video continuously while answering user queries with low latency. Recent methods reduce query-time cost by prefilling frames into KV caches during idle time and reusing the cached KVs at query time. To bound per-frame computation over unbounded video streams, these methods restrict the context available during prefill. This creates a fundamental context mismatch: the restricted context may omit information needed to properly contextualize video tokens, yet, still con-tain information irrelevant to the eventual query, which is unknown during prefill. We propose FrameBlend , a simple yet effective plug-and-play method to address this mismatch through selective KV recomputation, without requiring any addi-tional training. At query time, FrameBlend re-prefills selected video tokens us-ing query-relevant context and replaces their cached KVs with recomputed ones. Crucially, this recomputation enables shorter attention windows during idle-time prefill, substantially reducing prefill cost while improving accuracy. Experiments across three SVU frameworks and five streaming and offline benchmarks demon-strate accuracy gains of up to 3.9 pp. On RVS-Ego, FrameBlend reduces per-frame prefill FLOPs by over 20% and total processing time by 14–59% for retrieval-based frameworks, including the cost of query-time recomputation. These results demonstrate that a simple change in how contextualization is distributed between idle time and query time can improve the accuracy-efficiency trade-off for SVU. 

## 1 INTRODUCTION 

Recent video large language models (video-LLMs) have demonstrated strong video understanding capabilities (Li et al., 2024; Bai et al., 2025a;b). These advances, together with growing demand for real-time applications such as robotics (Mu et al., 2023), autonomous driving (Shao et al., 2024), and surveillance systems (Rao et al., 2022), have spurred interest in streaming video understanding (SVU). In SVU, a video-LLM continuously processes an incoming video stream and answers user queries as they arrive. This setting imposes three constraints. First, during idle time , i.e., no query is pending, the model must keep pace with a potentially unbounded stream under limited compute and memory. Second, because future queries are unknown during idle-time processing, it is difficult to decide in advance which information to preserve. Third, at query time , the model must respond with minimal latency, leaving little room for additional computation before answering. To meet these requirements, recent methods prefill incoming frames into key-value (KV) caches during idle time and directly reuse the cached KVs at query time (Di et al., 2025; Ning et al., 2026; Zhang et al., 2026). However, letting every incoming token attend to all preceding tokens incurs a cumulative attention cost that grows quadratically with stream length, which is prohibitive for long streams. Existing methods therefore limit the prefill context, either through sliding-window attention, which restricts attention to recent frames (Di et al., 2025; Chen et al., 2026a;b), or through KV cache compression, which condenses accumulated context into a fixed-size memory (Kim et al., 2025; Ning et al., 2026; Zhang et al., 2026). Both strategies can create a mismatch between the context used to construct KVs during idle-time prefill and the context used at query time. With KV cache compression, information from tokens that are later compressed or evicted may remain encoded in retained KVs, even when it is irrelevant to the query (Pang et al., 2026). Reused KVs may thus both omit relevant context and retain irrelevant context. Direct KV reuse leaves these representations uncorrected, potentially degrading answer quality (Yao et al., 2025). To resolve this mismatch, we propose FrameBlend , a training-free method that selectively recom-putes cached KVs at query time. Inspired by recomputation techniques in LLM serving (Yao et al., 2025; Hu et al., 2025), FrameBlend re-prefills a selected subset of tokens under the query-time con-text and overwrites their cached KVs. Whereas prior methods either rely on costly operations to identify recomputation targets or select them in a query-agnostic manner, FrameBlend uses QTS (query-relevant token-level selection), a lightweight, frequency-based mechanism guided by query relevance. Moreover, in SVU, query-time recomputation fundamentally changes how idle-time pre-fill should be designed; rather than using large attention windows to preserve context in advance, FrameBlend instead uses shorter windows, as missing context can be recovered once the query ar-rives. This not only reduces prefill cost but can also improve accuracy over longer windows. We attribute this gain to reduced contextual interference: since future queries are unknown at prefill time, shorter windows limit how much query-irrelevant information is baked into the cached KVs. Together, shorter attention windows during idle-time prefill and query-time KV recomputation form the core principle of FrameBlend, improving both efficiency and accuracy without training, and with minimal modifications to existing SVU frameworks. We evaluate FrameBlend on three SVU frameworks—ReKV (Di et al., 2025), HERMES (Zhang et al., 2026), and LiveVLM (Ning et al., 2026)—across two streaming benchmarks: RVS (Zhang et al., 2024) and OVO-Bench (Niu et al., 2025). We also assess general video understanding ability on three offline benchmarks (Fu et al., 2025; Zhou et al., 2025; Mangalam et al., 2023). FrameBlend matches or improves aggregate accuracy on every framework-benchmark pair, with gains of up to 3.2 pp on streaming benchmarks and 3.9 pp on offline benchmarks. For ReKV and LiveVLM, Frame-Blend further reduces per-frame prefill FLOPs by 22.2–26.0% and prefill latency by 12.6–60.5% on RVS. Even after accounting for query-time recomputation, total FLOPs and latency decrease by 19.0–23.2% and 14.1–58.7%, respectively. Our contributions are summarized as follows: • We propose FrameBlend, a plug-and-play, training-free method that selectively recomputes KVs for relevant tokens at query time. To our knowledge, it is the first query-aware recomputation method for SVU. • We show that query-time recomputation enables shorter attention windows during idle-time prefill, reducing prefill cost while matching or exceeding the accuracy of longer windows. 2Preprint • Across ReKV, HERMES, and LiveVLM on two streaming and three offline benchmarks, Frame-Blend consistently improves (or matches) aggregate accuracy for every framework–benchmark pair, with gains of up to 3.2 pp and 3.9 pp, respectively. For ReKV and LiveVLM on RVS, it also reduces per-frame prefill FLOPs by 22.2–26.0% and total latency by 14.1–58.7%. 

## 2 RELATED WORK 

Streaming video understanding. The central challenge in SVU is efficiently storing and utilizing the information in potentially unbounded video streams, under memory and computation constraints. One line of work addresses this by maintaining an explicit memory of visual representations from in-coming frames (Zhang et al., 2024; Qian et al., 2025; Wang et al., 2025; Zeng et al., 2025). However, these stored representations must still be processed by the backbone LLM to answer the incoming query, often leading to long query-time latency for LLM prefill computation. Recently, a growing line of work instead prefills incoming frames into KV cache during idle time and directly reuses the cached KVs at query time, thereby shifting much of the prefill computation to idle time (Di et al., 2025; Chen et al., 2026b;a; Kim et al., 2025; Yang et al., 2025; Ning et al., 2026; Zhang et al., 2026). These approaches can be categorized according to how they manage the context during the prefill and decoding. During prefill, allowing each frame to attend to all preceding frames becomes prohibitively expensive as the stream grows. Therefore, some approaches restrict attention to recent frames using sliding-window attention (Di et al., 2025; Chen et al., 2026b;a), while others apply KV cache compression to reduce redundant tokens (Kim et al., 2025; Yang et al., 2025; Ning et al., 2026; Zhang et al., 2026). During decoding, retrieval-based methods independently select query-relevant KVs at each layer based on their similarity to the query (Di et al., 2025; Chen et al., 2026a; Ning et al., 2026). In contrast, non-retrieval methods use the entire bounded KV memory, which has been progressively compressed during prefill, to generate the final prediction at the query time (Kim et al., 2025; Yang et al., 2025; Zhang et al., 2026). These works directly reuse the stored KVs for decoding, which can create a context mismatch be-tween prefill and decoding. Our work mitigates this mismatch by selectively recomputing cached KVs with query-relevant context at query time. 

Selective recomputation of KV cache. The idea of recomputing the cache for resolving context mismatch has been studied recently in the field of long-context LLMs. In these scenarios, the pri-mary goal is to approximate the behavior of full-context KVs, by recomputing only a fraction of the KVs that have been previously prefilled by computing in short chunks. For example, CacheBlend dynamically selects and recomputes the KVs for tokens that deviate large by such recomputations (Yao et al., 2025). EPIC instead statically recomputes the first few tokens of each cached chunk (Hu et al., 2025). These ideas have been extended to vision-language model serving, where MPIC re-computes the first few image tokens (Zhao et al., 2025), while VLCache dynamically adjusts the recomputation ratio across layers (Qin et al., 2025). These methods, however, are not specifically designed for SVU, where recomputation must be both query-aware and efficient under a tight query-time latency budget. Their recomputation targets are determined either by query-agnostic heuristics or by additional query-time operations. In contrast, FrameBlend selects query-relevant recomputation targets and leverages existing backbone retrieval results where applicable, thereby minimizing additional target-selection operations.

## 4 METHOD 

We propose FrameBlend , a simple yet effective plug-and-play method to reduce the prefill cost and improve the accuracy of SVU frameworks by selectively recomputing the KV cache at query time. We first formally describe how FrameBlend works (Section 4.1), and discuss how it allows us to use a shorter attention window (Section 4.2). By default, we focus on describing the case of applying on retrieval-based methods, e.g., ReKV (Di et al., 2025) or LiveVLM (Ning et al., 2026). Then, we additionally discuss how to adapt it for KV compression methods, e.g., Zhang et al. (2026). 4Preprint 4.1 SELECTIVE RECOMPUTATION OF KV C ACHE 

After the base SVU framework (e.g., ReKV) determines the layerwise KV sets {S ℓ}Lℓ=1 for answer-ing the query q, FrameBlend operates in two simple steps: (1) Recomputation target selection: We select a subset of the loaded KV sets to recompute; (2) Recomputing and decoding: We recompute the KVs and use them for decoding the answer. We describe each step below. 

Step 1: Recomputation target selection. In this step, we select a subset of the retrieved KV cache 

Sℓ that will be recomputed, using the QTS (query-relevant token-level selection) criterion. The design principle of QTS is twofold. First, we prioritize the most query-relevant KVs, because they will have the largest impacts on the final answer. Second, we select KVs in a way that recom-puting can be done efficiently, in order to minimize the query-time latency. Typical recomputing methods for LLM serving, e.g., CacheBlend (Yao et al., 2025), are suboptimal in this sense; they focus on approximating the properties of full KV cache by recomputing KVs that get updated the most, gradually proceeding over the layers. This is not aligned well for SVU, being query-agnostic and requiring a tedious sequential selection procedure between transformer layers. In short, QTS makes selection at the token-level, i.e., select KVs corresponding to the same tokens at every layer. This design is geared toward minimizing the latency, by enabling an allocation of constant computational budget over the layers and removing any inter-layer operations. QTS selects the tokens that have been most frequently selected as Sℓ across all layers. More con-cretely, the set of recomputation target tokens is defined as

## 5 EXPERIMENTS 

5.1 EXPERIMENTAL SETUP 

Benchmarks. We evaluate FrameBlend on five streaming and offline video understanding bench-marks, covering both multiple-choice and open-ended question answering. For streaming evalua-tion, we use OVO-Bench (Niu et al., 2025) and RVS (Zhang et al., 2024). On RVS, following Zhang et al. (2026), we use GPT-3.5-turbo-0125 to evaluate open-ended answers. For offline evaluation, we use MLVU (Zhou et al., 2025), Video-MME (Fu et al., 2025), and EgoSchema (Mangalam et al., 2023). We use the official development set for MLVU, the full EgoSchema test set evaluated by the official evaluation server, and Video-MME without subtitles. 

Base SVU methods. To evaluate FrameBlend as a plug-and-play method, we integrate it into three frameworks: ReKV (Di et al., 2025); LiveVLM (Ning et al., 2026); HERMES (Zhang et al., 2026). We retain the original configuration of each framework except for applying the query-time recom-putation and the short prefill window introduced by FrameBlend. 

Video-LLMs. We evaluate on two open-weight backbone video-LLMs: LLaVA-OneVision-7B (LLaVA-OV-7B) (Li et al., 2024) and Qwen2.5-VL-7B (Bai et al., 2025b). 

Hyperparameters. All video inputs have been sampled at 0.5 FPS. We set the recomputation budget to K = 7840 video tokens, corresponding to 40 frames for LLaVA-OV-7B. For FrameBlend, we have tuned prefill window sizes for each framework-benchmark pair. 

Hardware. All efficiency experiments have been conducted on a single NVIDIA A100 80GB GPU.

We compare QTS with CacheBlend (Yao et al., 2025) to evaluate the effect of recomputation target selection. For a controlled comparison, we follow the released CacheBlend implementation while using the same prefill window size and KV replacement policy as FrameBlend. This setup isolates the effect of target selection: the CacheBlend-based variant fully recomputes early layers to identify targets in a query-agnostic manner, whereas QTS directly selects query-relevant targets without such additional computation. As shown in Table 4, FrameBlend consistently achieves higher accuracy with lower added TTFT across all streaming benchmarks. These results show that QTS provides a more favorable accuracy–latency trade-off for selective recomputation in SVU. 5.5 ABLATION STUDY

As shown in Table 5, applying either component alone has mixed effects across benchmarks. A shorter prefill window removes part of the inter-token context, which can reduce unnecessary context but may also discard useful context for answering the query. Query-time recomputation complements this by selectively restoring query-relevant context among the selected tokens. ## 6 CONCLUSION 

In this work, we introduced FrameBlend, a simple yet effective plug-and-play method for SVU. FrameBlend addresses the context mismatch in prior SVU frameworks by selectively recomput-ing cached KVs at query time without requiring any training. To enable efficient recomputation under the tight query-time latency budget of SVU, we propose QTS, which selects query-relevant recomputation targets with minimal additional overhead. We further show that, with query-time recomputation, using shorter attention windows during idle-time prefill can improve performance while substantially reducing computation. Evaluated across three SVU frameworks and five stream-ing and offline video understanding benchmarks, FrameBlend consistently improves (or matches) performance while reducing the overall computational cost. 

Limitations. While FrameBlend improves accuracy and overall efficiency, several limitations re-main and could be addressed in future work. Although we evaluate FrameBlend across multiple SVU frameworks, video-LLM backbones, and benchmarks, our experiments are limited to 7B-scale backbone models, and its effectiveness on both smaller and larger models remains to be explored. In addition, FrameBlend currently uses a fixed prefill window selected for each framework and benchmark; automatically adapting the window to different video streams could further improve its practicality. Finally, although FrameBlend reduces overall computation, selective recomputation introduces additional query-time latency. ## A FRAMEWORK -S PECIFIC IMPLEMENTATION DETAILS 

A.1 REKV WITH FRAME BLEND 

ReKV (Di et al., 2025) stores the KVs of all incoming frames and independently retrieves the top 64 frames at each LLM layer when a query arrives. During idle-time prefill, the original ReKV lets each token attend to up to 15,000 preceding video tokens using a sliding-window attention. We apply the short prefill window of FrameBlend by changing only this window size; the retrieval and decoding procedures remain unchanged. For recomputation target selection, we directly use the layer-wise retrieval results produced by ReKV. Because ReKV retrieves complete frame blocks, all tokens within a frame block share the same retrieval score; QTS therefore operates at the frame level. We first rank each frame by the number of layers in which it is retrieved. Ties are broken by the sum of its normalized retrieval scores over the layers that retrieve it. The selected frames are ordered temporally and jointly re-prefilled through all LLM layers. At each layer, only frames that are both selected for recomputation and present in that layer’s original retrieval set are replaced by their recomputed KVs. Therefore, FrameBlend does not add frames to the layer-wise decoding context or modify ReKV’s retrieval policy. A.2 LIVE VLM WITH FRAME BLEND 

LiveVLM (Ning et al., 2026) processes incoming frames while maintaining a compressed KV cache. It applies compression when the cache exceeds its budget of 12,000 tokens. At query time, it inde-pendently retrieves 40% of 16-token pages for each layer and head. The resulting query-time context can therefore contain different video tokens across both layers and heads. FrameBlend uses sliding-window attention with a separate, small KV buffer, allowing each incom-ing token to attend only to the most recent tokens of the original stream within the prefill window. The separate KV buffer ensures that the effective window size does not depend on how much the KV cache has been compressed. For QTS, we use the tokens selected by LiveVLM’s retrieval mech-anism as candidates. Because LiveVLM has different retrieval sets for each layer–head pair, we count how many layer–head pairs retrieve each token. We then select the most frequently retrieved tokens based on this count, using normalized retrieval scores for tie-breaking. The selected tokens are jointly re-prefilled, and only their corresponding slots in the temporary query-time cache are replaced. A.3 HERMES WITH FRAME BLEND 

HERMES (Zhang et al., 2026) maintains a compressed KV cache instead of performing query-time retrieval. We set the maximum KV cache size to 6,000 video tokens, and HERMES independently compresses the cache at each layer to this budget. The original HERMES allows incoming tokens to attend to the entire compressed cache. For FrameBlend, as in LiveVLM, we restrict this prefill attention to the most recent video tokens within the prefill window using sliding-window attention. We also maintain a separate KV buffer containing the uncompressed KVs of these recent tokens for the same reason as in LiveVLM. Because HERMES has no query-time retrieval, we perform an auxiliary retrieval forward pass only for recomputation target selection. At each layer, we retrieve the top-M video tokens using their query similarity and use these layer-wise sets as the voting sets for QTS. We use M = 2 ,048 for RVS and M = 4 ,096 for OVO-Bench and the offline benchmarks. We then rank tokens by the number of layers that select them and choose the most frequently retrieved tokens. This auxiliary retrieval affects only which KVs are recomputed; the decoding context remains the full compressed KV cache produced by HERMES. The selected tokens are re-prefilled in temporal order using the layer-specific position indices maintained by HERMES, and the recomputed KVs replace only the corresponding surviving slots in each layer. 13 Preprint Table 6: Prefill window sizes used by FrameBlend. ## C ADDITIONAL PREFILL WINDOW SIZE ANALYSIS 

To further examine how the prefill window affects performance, we sweep the window size under full recomputation ( K = ∞) for ReKV with FrameBlend for simplicity. As shown in Figure 6, performance typically peaks at a particular window size rather than improving monotonically as the window grows. Overall, prefill windows shorter than ReKV’s default window of 15K tokens tend to perform better, while the optimal window size varies across benchmarks. Even when the window is relatively large, such as 8K tokens, it is still only about half of the default window size. This also suggests that the appropriate amount of idle-time context is benchmark-dependent, making automatic adaptation of the window size to the video stream an interesting direction for future work.
